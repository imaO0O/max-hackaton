# Разбор кода перед защитой

По правилам хакатона команда должна сама понимать решение и уметь объяснить принятые решения. Этот документ — маршрут по коду примерно на час и вопросы, которые вероятно задаст жюри. Пройдите его вдвоём: один объясняет, второй задаёт вопросы, потом поменяйтесь.

## 1. Карта проекта (5 минут)

| Где | Что | Кто отвечает на защите |
|---|---|---|
| `packages/core/src/grades.js` | калькулятор среднего балла аттестата | Б |
| `packages/core/src/plan.js` | какие даты попадают в план, статусы, расписание напоминаний | А |
| `apps/server/src/api` | HTTP API мини-приложения, проверка подписи MAX, ограничение частоты | А |
| `apps/server/src/bot` | диалог бота: опрос (`survey.js`), меню, план и план семьи в чате (`plan-chat.js`), колледжи (`colleges-chat.js`), сравнение путей (`paths-chat.js`), свободный текст (`free-text.js`), оформление (`rich-text.js`), клавиатуры (`keyboards.js`), тексты | А |
| `apps/server/src/scheduler` | отправка напоминаний | А |
| `apps/server/src/services` | сценарии: план, каталог, календарь, метрики | А |
| `apps/server/src/repositories`, `db` | SQL, миграции, загрузка справочников | А |
| `apps/miniapp/src/screens` | экраны мини-приложения | Б |
| `apps/miniapp/src/lib/max-bridge.js` | обёртка MAX Bridge с запасными вариантами | Б |
| `data/*.json` | справочники: регионы, колледжи, даты, тексты | Б |

Точка входа сервера — `apps/server/src/index.js`: собирает зависимости (`container.js`), пересобирает напоминания, запускает бота, планировщик и HTTP-сервер.

## 2. Пять сценариев, которые надо уметь рассказать по коду

### Опрос в боте (А)

1. `bot.js` → `bot.action(/^survey:/)`: каждая кнопка — callback с payload `survey:<шаг>:<значение>`.
2. Черновик ответов хранится в базе (`users.survey_state`), а не в памяти — опрос переживает перезапуск сервера.
3. На последнем шаге `services.plan.saveProfile` проверяет регион, класс, путь и город по справочникам и пересобирает напоминания.
4. В ответ бот присылает сводку, три ближайшие даты (`planText` в `texts.js`) и кнопку «Открыть план».

Проверка себя: что будет, если нажать кнопку старого опроса? (`restart()`: с готовым планом — «Ответы уже сохранены» и меню, без плана — «Этот вопрос устарел»; тест в `bot-dialog.test.js`.) А если ошибся в ответе? (`survey:back:<шаг>` — шаг назад без потери ответов.)

### Весь сценарий в чате (А)

1. `plan-chat.js`: меню, ближайшие даты, «Все даты года» с кнопкой на каждую дату, карточка пункта с отметкой.
2. Переходы по кнопкам редактируют одно сообщение (`answerOnCallback`), команды присылают новое.
3. «Отправить план подростку» даёт диплинк `https://max.ru/:share?text=…` и сообщение для пересылки с двумя ссылками: `?startapp=plan_…` (мини-приложение) и `?start=plan_…` (чат с ботом — приходит в `bot_started` как payload).
4. Напоминание родителю — с кнопкой «✅ Сделано»: она ставит отметку, и следующие напоминания по пункту снимаются пересборкой очереди. Кнопки под напоминанием (`ritem:`, `rdone:`, `rundo:`) не редактируют его текст: «Сделано» меняет только кнопку, «Подробнее» присылает новое сообщение.
5. Подписчик без своего плана видит план семьи: `currentPlan()` в `plan-chat.js` возвращает свой план, а если его нет — план, на который пользователь подписан (`getFollowedShareToken`).
6. Свободный текст: `detectTopic()` в `free-text.js` узнаёт тему по ключевым словам (порядок правил важен), `bot.js` отправляет в нужный раздел. Без ИИ: ответ предсказуем, текст не сохраняется.

Проверка себя: почему подписчику не показываем «Сделано»? (План принадлежит родителю; отметки подростка ломали бы план семьи.) Почему «когда отбор в 10 класс» — это даты, а не сравнение путей? (Правило `plan` стоит раньше `paths`; тест в `free-text.test.js`.)

### Мини-приложение узнаёт пользователя (А)

1. MAX открывает мини-приложение и кладёт подписанные данные запуска в `window.WebApp.initData`.
2. `apps/miniapp/src/lib/api.js` отправляет их в заголовке `X-Max-Init-Data`.
3. `apps/server/src/api/init-data.js`: ключ = HMAC-SHA256("WebAppData", токен бота), подпись = HMAC-SHA256(ключ, отсортированные пары key=value). Сравнение — `timingSafeEqual`, срок действия — `INIT_DATA_MAX_AGE_SECONDS`.
4. Хук в `app.js` пускает к личным маршрутам (`config: { auth: true }`) только с верной подписью.

Проверка себя: почему нельзя просто передать ID пользователя в запросе? (Его можно подделать; подпись может выдать только MAX, токен бота знает только сервер.)

### План года (А и Б)

1. `plan-service.js` → `buildPlanFor`: учебный год по дате (`academicYearFor`), для 8 класса — следующий (`planYearFor`).
2. `core/plan.js` → `matchesProfile`: дата попадает в план, если совпадает учебный год, регион (для региональных), путь (или семья «пока не знает») и режим эксперимента с двумя ОГЭ.
3. Статус «прошло / идёт / впереди» и число дней считаются по времени региона (`utcOffsetHours`).

Проверка себя: как добавить новый регион? (Только данные: `regions.json`, `colleges.json`, региональные даты — см. `data/README.md`. Код не меняется — это и есть масштабирование.)

### Напоминания (А)

1. `reminderSchedule` превращает правила из справочника (`reminders: [{ anchor, daysBefore }]`) в время отправки — 10:00 по времени региона.
2. Очередь в таблице `reminders` пересобирается при сохранении профиля, отметке пункта, подписке подростка, при старте сервера и раз в сутки — поэтому изменение дат в справочнике и смена учебного года подхватываются сами.
3. Планировщик раз в 5 минут отправляет наступившие. Временная ошибка — до 3 повторов, 403/404 (бот заблокирован) — без повторов, опоздание больше суток — не отправляем.

Проверка себя: подросток подписался на план родителя — откуда у него напоминания? (`plan_followers` + `syncReminders` кладёт то же расписание и ему.)

### Средний балл (Б)

1. `core/grades.js` → `calculateAttestat`: по предметам ОГЭ итоговая — среднее годовой и экзаменационной с математическим округлением, по математике — по трём курсам (приказ № 546).
2. Считается прямо на телефоне, оценки лежат в `localStorage` и на сервер не уходят.
3. «Где проходили с моим баллом» сравнивает расчёт с прошлогодним проходным — это ориентир, не прогноз.

## 3. Решения, которые надо уметь объяснить

| Решение | Почему так | Что сделали бы после пилота |
|---|---|---|
| Один процесс: API, бот, планировщик | для MVP проще развернуть и проверить; нагрузка пилота — сотни семей | разделить на сервисы, общая база, блокировка задач планировщика |
| SQLite (`node:sqlite`) | ноль внешних сервисов, запуск одной командой, копия базы — один файл | PostgreSQL при нескольких экземплярах |
| Long polling, а не webhook | не нужен публичный адрес для бота, проще локально | webhook при росте нагрузки |
| Справочники в JSON в репозитории | данные проверяет валидатор и ревью, у каждого факта источник и дата | админка для региональных операторов |
| Без языковой модели | ответы о сроках и правилах должны опираться на первоисточник, модель может ошибиться | — |
| Весь сценарий ещё и в чате | если мини-приложение не откроется, основной сценарий всё равно проходится: план, отметки, отправка подростку, подписка | — |
| Календарь по одноразовой ссылке | `downloadFile` скачивает без заголовков авторизации, поэтому подпись в самой ссылке и срок 10 минут | — |

## 4. Вероятные вопросы жюри

**Какие персональные данные вы храните?** ID пользователя в MAX, ответы опроса (регион, город, класс, интересы, путь), отметки, избранное, расписание напоминаний. Имён и оценок нет. Удалить всё можно командой `/delete_data` — каскадно по внешним ключам, в метриках ID обнуляется.

**Где секреты?** Только в `.env` на сервере, в репозитории — `.env.example` без значений. Токен бота нужен и боту, и для проверки подписи мини-приложения.

**Что реальное, а что модельное?** Бот, мини-приложение, подпись MAX, напоминания, календарь — работают. Данные Татарстана реальные, со ссылками; демо-регионы вымышленные и помечены. Интеграций с Госуслугами и «Моей школой» нет — это следующий шаг.

**Как вы проверяете, что всё работает?** Автотесты ядра и сервера (`npm test`), включая диалог бота с подменённым Bot API; GitHub Actions на каждый PR: тесты, Docker-сборка с замером времени, запуск контейнера. Ручная проверка — `docs/max-check.md`.

**Что будет, если MAX API недоступен?** Опрос MAX перезапускается автоматически, бот раз в 5 минут проверяет связь; после трёх сбоев `/api/health` показывает `degraded`, в логах ошибка.

**Как измерите эффект?** События воронки в журнале: начали и прошли опрос, открыли план, отправили подростку (подросток открыл ссылку), подписка, возвраты из напоминаний, календарь. Отчёт — `/stats`.

**Как масштабировать?** Ядро (логика плана, экраны, модель данных) не меняется; для региона нужны колледжи, региональные даты и правила отбора в 10 класс. Порядок: Татарстан → остальные регионы эксперимента с двумя ОГЭ → остальные регионы.

**Почему не Госуслуги / «Сферум»?** Там нет планирования выбора пути для семьи; «Напоминатель» в «Сферуме» — напоминания от учителя. Мы дополняем их, а не заменяем.

**Использовали ли ИИ?** Да, как помощника при написании кода и черновиков документации — правила это разрешают. Архитектуру, данные региона и продуктовые решения команда выбирала и проверяла сама и может объяснить каждую часть.

## 5. Упражнения на час

1. Запустите `npm test` и найдите тест, который проверяет подделанную подпись (`init-data.test.js`).
2. Поменяйте в `data/key-dates.json` дату одного пункта, запустите `npm run data:check` и сервер — проследите в логах «reminders resynced on startup».
3. Добавьте в `.env` свой ID в `ADMIN_USER_IDS` и посмотрите `/stats` в боте.
4. Объясните друг другу без подсказок: что происходит от нажатия «Открыть план» до появления экрана.
